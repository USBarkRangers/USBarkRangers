# Apple sign-in and deletion recovery — 0.5.26 (85)

## Confirmed causes and fixes

- **Apple nonce transport:** the adapter generated a Base64 raw nonce. Firebase's pinned `VerifyAssertionRequest` sends it in a form body built with `URLComponents.query`; an unescaped `+` can become a space when decoded. The screenshot's mismatch was verified locally without replaying a token or logging its values. The adapter now represents the same 32 cryptographically random bytes as lowercase hex. Request identity, hashing, state validation and single-use consumption remain enforced.
- **Device cleanup:** a full-URL equality check rejected a valid, exact-owner deletion marker. The Mac reproduction showed `/var` versus `/private/var` aliases. Canonicalizing the input fixed that reproduction but was insufficient on the actual iOS 27 phone: build 84 still reported `removeAccountData / accountChanged` and retained the correct marker. Build 85 instead checks the exact hashed owner filename among the known folder's directly enumerated children. Project/owner validation and exact erasure targets remain. No broad deletion or reset was added.
- **Recovery after failure:** failed startup left a finished authentication task installed, so subsequent starts did nothing while sign-in controls still looked usable. Startup now has explicit checking/ready/failed feedback, releases the failed task, and offers one Retry device cleanup action. Authentication is disabled until cleanup succeeds. Cancellation drains the old authentication task before storage cleanup. Deletion also preserves the app's actual foreground state so the next account can synchronize without a relaunch.
- Firebase's nonce error is translated to an actionable message instead of displaying its raw security values. Cleanup diagnostics use fixed stages/classified reasons, not account IDs, tokens or user text.
